# ADR-001 — Arquitetura Modular

## Status

Aceito

---

## Contexto

Inicialmente, toda a aplicação estava concentrada em poucos arquivos JavaScript.

Com o crescimento do projeto, o código tornou-se mais difícil de entender, modificar e manter.

Além disso, diferentes responsabilidades estavam misturadas no mesmo arquivo, dificultando futuras evoluções.

---

## Decisão

Foi adotada uma arquitetura modular.

O projeto passou a ser organizado em diferentes pastas, cada uma com uma responsabilidade específica:

- data
- models
- services
- utils

Essa organização facilita a manutenção e a reutilização do código.

---

## Consequências

### Positivas

- Melhor organização do projeto;
- Separação de responsabilidades;
- Código mais fácil de entender;
- Facilidade para manutenção;
- Maior reutilização de código.

### Negativas

- Aumento da quantidade de arquivos;
- Maior número de imports;
- Necessidade de atenção aos caminhos relativos;
- Controle das dependências entre módulos.
